# InvisAttackSim

通过事件驱动的蒙特卡洛模拟，估计 BedWars 简化模型中固定队伍遭遇隐身攻击的时间事件密度，计入同局的全部有效攻击。

## 当前状态

当前实现为 **m2.1 移动追击基准**，已通过 68 项测试与 30,000 局逐事件审计。四队各一名玩家、一个中间岛的地图保持不变；增加无床目标的空间追踪、实际相遇后的双人战斗，以及跨床毁连续进攻去重。观察持续至我方淘汰或对局结束，不再因我方床毁或到达 30 分钟停止。

M1 阶段终点为 m1.3，可通过 Git 标签 `m1-complete` 取得源码和配置。新版本改变行为与输出协议，历史数值不能当作当前验收结果。已与现有汇总记录完成描述性比较；真实记录采集由同组负责，严格数据对齐与校准尚未完成。进度见 [开发路线](docs/ROADMAP.md)，检查见 [验证说明](docs/VALIDATION.md)，变更见 [更新日志](docs/CHANGELOG.md)。

## 模型与计数

有床时统计对手在隐身状态下朝我方越过基地路线边界（从中间岛量起全程的 1/4）。我方无床后，统计以我方为目标、仍有药效且进入我方周围 2.5 秒现成桥路程范围的进攻。沿可通行路线测距；进入范围不要求命中。

每个进攻轮次最多计一次。短暂离开再进入范围，以及同一连续进攻拆床后转入追杀，都不新增主事件；后者可附加追杀标签。撤退、死亡或行动被中断后，本轮结束。逐次结果分别记录首次计入时的我方床状态和攻击者床状态。

所有当前可攻击敌队一起等概率选为进攻目标。有床时攻击基地，无床且存活、可达时追踪玩家。追击者知道目标当前位置，目标接战前继续原行动。追击只沿已建桥走最短路径，不为追人搭桥；双方现成桥单程均为 10 秒。统计范围与接战不同：距离为 0、实际相遇才交战，接近最多 30 秒。

新发起的无床目标隐身进攻立即喝药，接近阶段药效到期即撤退；跨床毁保留原轮次和余效。相遇后双方停止原行动，战斗 U(5,20) 秒，进攻者击杀率 60%；药效在战斗中到期不取消结算。每人最多参与一场双人战斗，第三名追击者到达则撤退。存活者从实际相遇位置返程后重新决策。资源生成、共享桥、购药与死亡转移等保留原有基准。

令 t 为开局后秒数，默认时间参数为：

```text
收集基础比例 c(t) = max(0.20, 0.80 - t/3600)
进攻内隐身基础占比 q(t) = min(0.80, 0.20 + t/3600)
收集 / 普通进攻 / 隐身进攻基础权重 = c / (1-c)(1-q) / (1-c)q

f = min(1, max(0, t/1800))
普通拆床率 = 0.08 * exp(-ln(8/3) * f)
隐身拆床率 = 0.60 - 0.20 * f
```

收集与隐身份额在 36 分钟达到 20%、80% 后保持。拆床率在 30 分钟后保持 3%、40%，按实际拆床结算时间取值，不用来结算无床战斗。

无床玩家的隐身/普通进攻权重比乘 2，收集和总进攻基础权重保持不变；随后过滤资源不足、无效目标等不可执行行动并归一化。进攻失败或中岛相遇退出时，有床条件死亡率 60%，无床为 30%，其余撤退。这不改变双人战斗的 60% 击杀率。不加入定时全体床毁等额外后期世界事件。

## 运行

需要 Python 3.11 和 uv。在项目根目录执行：

```bash
uv sync --no-editable
uv run --no-sync invis-attack-sim run --config configs/default.json --output outputs/m2.1 --audit
```

默认 10,000 局、种子 42、5 秒输出分箱。覆盖局数、种子或分箱宽度：

```bash
uv run --no-sync python -m invis_attack_sim run --trials 1000 --seed 43 --bin-width 60 --output outputs/quick
```

5 秒和 60 秒都只用于结果分箱，移动与接战按事件时间和连续位置计算。修改源码后，在当前 macOS 环境使用 `uv sync --no-editable --reinstall-package invis-attack-sim` 更新安装，再运行 `--no-sync`；开发时也可使用 `PYTHONPATH=src .venv/bin/python -m invis_attack_sim ...`。

配置 `max_time` 默认为 `null`，没有固定观察时长上限；`max_events` 默认每局 100,000 个处理事件，仅为技术保护。可用 `--max-time` 临时限制诊断运行。保护触发时记作未完成，命令返回 2，原始事件保留但该局不进入主分母。旧配置的 `horizon` 不再支持；复现 M1 应使用里程碑版本及其配置。

## 输出与分母

| 文件 | 内容 |
| --- | --- |
| `attack_density.png/svg` | 所有有效隐身攻击的时间事件密度 |
| `interval_probability.png/svg` | 每箱至少一次攻击的概率 |
| `density.png/svg` | 两者组合图 |
| `histogram.csv` | 总次数、两种我方床状态的次数与密度、攻击者床状态、命中对局数及完整对局分母 |
| `trials.csv` | 完整性、攻击次数、床毁时间、观察终点与原因 |
| `attacks.csv` | 所有尝试对局的逐次事件，含完整性、轮次、类型、攻击者床状态及后续追杀标签 |
| `config.json` | 完整运行配置 |
| `summary.json` | 模型和 schema 版本、源码指纹、完整/未完成数量、排除原因及主统计 |

输出 schema 为 3；时间单位为秒。统一时间轴延展至完整对局的最晚观察终点所在箱，最后一箱仍按完整箱宽计密度，并包含最终右端点。真实对比可用 60 秒分箱。

```text
N = 符合完整观察协议的全部对局数，含零事件和正常提前结束的对局
事件密度 = 该箱全部有效事件数 / (N × 箱宽)
至少一次概率 = 该箱有事件的对局数 / N
```

密度积分等于每局平均攻击次数，可以大于 1；区间概率在 0–1 之间。同轮后续追杀标签不另加一次。技术截断不补零，摘要单列排除原因；如果没有完整对局，主统计为 `null`、分箱表只有表头，图表注明无可用完整样本。

## 验证

```bash
PYTHONPATH=src .venv/bin/python -m unittest discover -s tests -v
uv run --no-sync invis-attack-sim stability --output outputs/stability --audit
```

稳定性命令默认运行 10,000 / 40,000 / 160,000 局和三个种子，用统一时间轴比较每局平均累计事件曲线。误差按整局 bootstrap 处理，默认 400 次；超过近似 95% 同时误差带返回 1，出现未完成对局返回 2，不记为通过。这检验数值抽样稳定性，不代表已验证真实对局适用性。

## 目录结构

```text
configs/default.json        当前默认参数
src/invis_attack_sim/
  config.py                 参数及时间曲线
  engine.py                 事件调度、行为与审计
  spatial.py                星形路线距离与连续运动交会计算
  results.py                完整对局统计与整局 bootstrap
  output.py                 CSV / JSON 和图表
  cli.py                    run / stability
tests/                     规则、统计和导出回归测试
docs/                      开发路线、验证及更新日志
outputs/                   生成结果，Git 忽略
.local/                    内部规格、讨论及实验，Git 忽略
```

源码、配置、测试和公开说明纳入版本控制；内部讨论及真实数据不随仓库发布。
