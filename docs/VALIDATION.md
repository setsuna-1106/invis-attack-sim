## 行为与输出检查

运行 `python -m unittest discover -s tests -v` 检查配置校验、生成时钟与库存、收集等待和拾取公平性、搭桥与返程、相遇取消、目标变化、死亡后动作取消及重生资格。测试还覆盖隐身越界与拆床同刻发生、隐身恰好到期及观察上限端点。

全次数回归检查包含同刻多个攻击者、同一攻击者后续进攻、同一移动事件不重复计数，以及同一箱内多次攻击与至少一次攻击概率的区别。同配置与种子重复运行时，逐局、逐次攻击和分箱 CSV 应完全一致。`--audit` 在每个事件处理后检查状态约束。

输出检查要求：

- `attacks.csv` 行数与逐局攻击次数之和、分箱事件数之和、摘要攻击总数一致。
- 事件密度积分等于每局平均攻击次数，允许大于 1。
- 每箱至少一次攻击概率在 0–1 之间，同局同箱多次攻击只计一个命中对局。
- 有攻击对局比例加零攻击对局比例为 1；不把事件密度积分加零攻击概率归一化为 1。

## 样本稳定性

`stability` 默认运行 10,000 / 40,000 / 160,000 局和三个不同种子，比较每局平均累计攻击次数曲线。检查时间点为所有 5 秒分箱的右端点，包含最终右边界。

同一局中的多个事件相关，不能把攻击当作相互独立样本直接套用首事件的 DKW 界。新版对最后两组分别**按整局重采样**，每次保留该局全部攻击，生成两组相对于观测均值的累计次数偏差；以它们之差在所有检查时间点的最大绝对值，构建近似 95% bootstrap 同时误差带。默认重采样 400 次，种子为基准种子加 3；可用 `--bootstrap-repetitions` 调整。

观测到的两组平均累计次数最大差异不超过误差带时记为通过，超过则保留结果并返回非零退出码。此为近似抽样稳定性诊断，不是严格有限样本保证，也不验证真实对局模型或单个分箱密度精度。结果保存在 `stability.json`。
